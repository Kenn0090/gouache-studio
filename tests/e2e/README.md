# End-to-end tests

- `paths-material.cjs` checks native mouse-driven material painting in 2D/3D, all channels in one undo, compact saved coverage, editable Pen handles, selections/fills/strokes, duplication, saved paths, camera-independent surface painting and UV seams. `GS_LARGE=1` with `GS_NATIVE_CDP` adds actual 8K/16K material brush and undo checks on hardware.
- `bake-canvas.cjs` interleaves rotating viewport frames with GPU baking and compares baked pixels exactly. It also checks Clear layer undo, Preferences resizing/reopening, and stable 8K canvas mip filtering during strokes.

- `paint-repairs.cjs` uses the offline desktop frontend, optionally a native WebView2 instance via `GS_NATIVE_CDP`. It checks source-size baked-map editing, the layer icon/context action, persistent return links through 2D/3D saves and set renames, undo/redo, 16-bit height, project isolation, actual 3D spot/source healing on a blank layer over a material, outline-only cursors, and reuse of studio shadows during colour strokes. `large-materials.cjs` additionally checks real floor-shadow reuse during native 8K/16K projected strokes when `GS_LARGE=1`.

- `project-maps-psd.cjs` exercises the offline desktop frontend: New 3D Paint setup, 4K/8K/16K resolution labels, source-size map imports and file drops, map-driven normals/masks/materials, shelf assignment, per-set isolation, compressed project assets, save/reopen, actual canvas/material conversion flows, asset-only dirty tracking, and layered PSD placement/fit/undo. Set `GS_NATIVE_CDP` to an isolated desktop WebView2 instance; add `GS_PROJECT_LARGE=1` for real 8K/16K hardware checks with six materials and the Projects shelf open.

Each `*.cjs` file drives the web build (`dist-web/index.html?debug`) in Chromium with a software GPU (SwiftShader) and checks results by reading pixels back. The `?debug` flag exposes `window.__gs` hooks (see `src/js/core/boot.js`).

```bash
npm run build                 # in the repo root: builds dist-web/
cd tests/e2e && npm install   # Playwright + the libraries the app loads from a CDN (served locally in tests)
node baketab.cjs              # one test: prints PASS/FAIL lines, then ALL PASSED
./regress.sh                  # everything (about 18 minutes; JOBS=n sets how many run at once); results in regress.log
```

- Screenshots from tests go to `out/`.
- `wikishots.cjs`, `cageshots.cjs`, `bakeshots.cjs`, `convshots.cjs`, `quickshots.cjs` and `memshots.cjs` regenerate the wiki screenshots in `docs/wiki/images/`. `memshots.cjs` stubs the desktop bridge (a 32 GB machine) to show and check Preferences › Memory and disk as the desktop app has it.
- `canvas19.cjs` checks the Shape tool (with bevels), the Array tool and layer styles, and that they survive a .gouache round trip. `shots19.cjs` makes their guide screenshots.
- `bakecurv.cjs` checks curvature bakes (from the shape, from the normal with Flip green), the Bake panel's tabs, and sending bakes as layers or maps only.
- `bakeperf.cjs` times an AO + thickness bake on a bumpy high-poly and checks the result is smooth; `DIST=<folder> node bakeperf.cjs` runs it against another build to compare speed.
- `fixtures/` holds the models, images and font the tests load. `fixtures/big.obj` (a 2.4-million-triangle model) is generated by `bigobj.cjs` on first run.
- If Chromium isn't found, set `PLAYWRIGHT_BROWSERS_PATH` or run `npx playwright install chromium`.
- Don't rebuild while `regress.sh` is running; the tests load `dist-web/` as they go.
- `fixtures/samba.fbx` (an animated FBX from the three.js examples) isn't kept in the repository for licensing reasons; `v3.cjs` skips it when it's missing. Put any binary FBX there to test FBX import.

- `muzzle.cjs` checks the three muzzle flash styles, smoke and duration, deterministic variation, transparent output, presets, frame generation and undo/redo. On Windows it uses Edge; set `GS_BROWSER_CHANNEL` to override the browser channel.
- `performance-foundations.cjs` compares partial stroke results against full compositing, including nested groups, group masks, clipping, 16-bit pixels and wrapping. It checks worker packing, worker-failure fallback, asynchronous saves, lossless project round trips and scratch eviction without destroying live results. Uses Edge by default; set `GS_BROWSER_CHANNEL` for another installed Chromium channel.
- `viewport-performance.cjs` compares regional viewport copies and every mip level to full GPU generation, including 2K, 16-bit, non-square, one-dimensional and odd-size textures. It checks conservative mask/multi-map/height/filter/clipping fallbacks, projected brush pixels, cached mesh bounds, pixel-identical grain post reuse, settings/cache invalidation, view-only controls and grain in detached windows. Uses Edge by default; set `GS_BROWSER_CHANNEL` to override or `GS_VIEWPORT_BUILD=desktop` for the offline frontend. Work counts measure reduction, not hardware FPS.
- `texture-shelf-performance.cjs` checks that browsing all 119 built-in textures loads no full GPU originals, concurrent uses coalesce, imported libraries load metadata first, legacy previews persist without changing pixels, full-resolution pack export works, eviction preserves applied images and live guides, thumbnail jobs are bounded, and detached observers/deletion races are handled. Uses Edge by default; set `GS_BROWSER_CHANNEL` to override. Set `GS_SHELF_BUILD=desktop` to check the offline desktop frontend through a local server.

- `material-performance.cjs` checks compact fill values against full pixels at both depths; masks, blending, clipping, tint, arrays and filters; material undo/redo, duplication, channel removal, pixel conversion and resizing; new/legacy file compatibility and exact worker packing. It tests 26 textured library materials at 1K and 26 uniform fills with projected painting at 4K, opaque-image invalidation, lazy height buffers and camera map reuse. Set `GS_MATERIAL_BUILD=desktop` for the offline frontend. Pixel/work/memory checks do not predict hardware frame rates.

- `large-materials.cjs` serves the offline frontend and compares lazy library image materials with stored pixels at both depths, including masks, opacity, blend modes, clipping, arrays, filters, transformed UVs, baked maps, triplanar projection and tint. It checks packed half-float height reads/uploads/blending/undo, scalar viewport mip patches, material history, duplication, channel removal, rasterization, old-reader pixel compatibility, lossless recipe reopening and allocation limits. Set `GS_LARGE=1` for six real image materials and projected brush/undo/camera checks at 8K and 16K; this requires a hardware renderer and enough memory. `GS_SIZE=8192` or `16384` restricts that workload. `GS_NATIVE_CDP=http://127.0.0.1:<port>` connects to a separately launched desktop WebView2 test instance with an isolated user-data folder and remote debugging, routes its frontend to local `dist/`, and retains the native desktop bridge. Use a dedicated test profile: this reloads the app and must not target a normal project session. Large test timings include readbacks and are specific to the tested renderer; tracked texture bytes exclude mip storage and driver overhead.


- `studio-tools.cjs` checks the offline desktop frontend: sixteen artwork fonts, twenty brush presets and eight tips, real 2D Shift input and undo, projected 3D straight lines and camera invalidation, material-preview mesh/maps, texture-set rename/project round trip, exact 16-bit PNG samples, mesh-map exports, static FBX, transparent floor height/cache/opacity/softness/direction and skin controls. Set `GS_NATIVE_CDP` to an isolated desktop WebView2 debugging endpoint for hardware checks. If `out/fbx-check/node_modules/three` exists, it also imports the written FBX with Three.js FBXLoader and compares triangle, UV and normal counts; install Three.js in that test-only directory to enable it.
- `studio-preview.cjs` renders the supplied preview mesh with its maps, a smart material and a smart mask, saving examples under `out/studio-update`. It supports `GS_NATIVE_CDP` for the desktop renderer.
- `tool-menus.cjs` checks that only real Healing, Dodge/Burn and Gradient/Fill groups have arrows; single-option tools have neither arrows nor hold menus. It verifies each group's own choices, saved healing modes, real pointer/keyboard input, quick clicks, drag-to-select, cancelled holds, dismissal, independent brush settings, changing group icons, regular menus, toolbar positioning and 3D Paint. It serves the offline frontend and supports `GS_NATIVE_CDP` for an isolated desktop WebView2 instance.
